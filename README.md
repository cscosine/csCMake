# csCMake

CMake utilities for C++ projects: one way to define targets, find dependencies, install packages with components,
choose compile options per configuration and build on every platform with ready-made presets.

csCMake is made of two parts:

1. a **CMake library** (`csCMake.cmake` and `utils/`): `cs_*` commands on top of CMake's own, which register the
   targets of a project, track their dependencies, generate the installed `<namespace>Config.cmake` with components,
   and apply compile profiles;
2. **CMake presets** (`presets/`) for every supported platform, compiler and generator, generated by a small Python
   tool (`src/cscmake/`, standard library only) and committed, so projects use them without Python.

> **Status:** under active development. `main` is tagged `v0.1.0`; new features land on the `dev` branch. The next
> release renames the API: see [MIGRATION.md](MIGRATION.md).

## Quick start

csCMake lives next to the projects that use it, in a *workspace*:

```text
workspace/
  csCMake/          git clone of this repository
  myApp/            your project
```

`myApp/CMakePresets.json` includes the presets, `myApp/csCMakeProjectSetup.json` says where csCMake is:

```json
{ "version": 10, "include": ["${sourceParentDir}/csCMake/presets/csv1/cs-presets-all.json"] }
```

```json
{ "version": 10, "include": ["${sourceParentDir}/csCMake/presets/layout/sibling.json"] }
```

`myApp/CMakeLists.txt`:

```cmake
cmake_minimum_required(VERSION 3.31)
project(myApp VERSION 1.0.0 LANGUAGES CXX)
include(csCMake)

cs_initialize_project(NAMESPACE myApp CXX_STANDARD 20 DEFAULT_CONFIG Debug Release)

cs_add_library(core STATIC)
cs_target_sources(core PRIVATE core/Greeting.cpp PRIVATE_INSTALL core/Greeting.hpp)
cs_target_link_libraries(core PUBLIC myApp::cscmake_base_include)
cs_install_target(core core DEFAULT)
cs_finalize_target(core)

cs_finalize_project()
```

Configure, build, install and test, here with GCC and Ninja Multi-Config on Ubuntu 24.04 (`cmake --list-presets` lists
the presets of your machine):

```bash
cd myApp
cmake --workflow --preset workflow-csv1-linux-ubuntu24.04-x64-generic-gcc-default-ninjamulticonfig-debug-release
```

The package is installed in `workspace/install/<variant>/myApp/`, where other projects find it with
`find_package(myApp)`. [Getting started](docs/user/getting-started.md) explains each line.

## What it does

- **Targets**: `cs_add_library` / `cs_add_executable` register targets; output names get a postfix per configuration,
  so every configuration can be installed side by side. [Targets and sources](docs/user/targets.md)
- **Installed headers and include paths**: headers are included by their path from the project folder, in the build
  tree and once installed. [Targets and sources](docs/user/targets.md#include-paths)
- **Packages with components**: `cs_install_target` puts targets in components; the generated `<namespace>Config.cmake`
  loads the requested ones, the components they depend on and their `find_dependency` packages.
  [Installed packages](docs/user/install.md)
- **Dependencies**: `cs_find_package(... PUBLIC ...)` propagates a dependency to the consumers of the package; nested
  csCMake projects in one build. [Dependencies](docs/user/dependencies.md)
- **Build configurations**: Debug, Release, RelWithDebInfo and custom ones, with the configurations of the
  dependencies to link. [Build configurations](docs/user/build-configurations.md)
- **Compile profiles**: warnings, sanitizers, standard library checks and clang-tidy, by configuration, compiler and
  platform, per project or per target. [Compile profiles](docs/user/compile-profiles.md)
- **Presets**: Linux (Ubuntu 22.04 to 26.04, x64 and arm64, GCC and Clang), Windows (MSVC and clang-cl, Visual Studio
  and Ninja), macOS (Apple Clang, Ninja and Xcode); workspace layouts for side-by-side, standalone and CI setups.
  [Presets](docs/user/presets.md)
- **Checks**: every target and the project must be finalized, installed headers can be compiled on their own, and
  runtime dependencies are resolved per configuration (Visual Studio debugger `PATH`).

## Requirements

- CMake 3.31 or newer.
- Linux: GCC or Clang. Windows: MSVC or clang-cl, with Visual Studio or Ninja (from a Visual Studio developer
  environment). macOS (Apple Silicon): Apple Clang, with Ninja or Xcode.
- Python 3.11 or newer only to develop csCMake (preset generator, tests, documentation).

## Repository layout

```text
csCMake.cmake          entry point: include(csCMake)
utils/                 the CMake modules (cs_* commands)
templates/             template of the generated <namespace>Config.cmake
presets/               the presets: common blocks, templates, generated csv1/, project setup and layouts
src/cscmake/           Python: preset registry and generator, dev tools
tests/                 Python tests, CMake configure tests (tests/cmake/), smoke projects (tests/smoke/)
docs/                  the documentation (Sphinx)
```

## Development

```bash
./setup.sh                      # .venv, the package in editable mode with the dev tools, pre-commit (Windows: setup.ps1)
source .venv/bin/activate
python -m pytest                # fast tests; --run-all adds the smoke builds of this machine
sphinx-build -W -n docs docs/_build/html
```
