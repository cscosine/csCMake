# Installed packages

Installing a csCMake project produces a CMake package: its targets, headers and a generated
`<namespace>Config.cmake`, so another project uses it with `find_package(<namespace>)`.

## Components

```cmake
cs_install_target(core core DEFAULT)
cs_install_target(text text)
cs_install_target(myTool tools)
```

`cs_install_target` installs a target in a *component* of the package. A component is what a consumer
asks for with `find_package(<namespace> COMPONENTS <component>...)`; it holds one or more targets. `DEFAULT` adds the
component to the ones loaded when the consumer gives no `COMPONENTS`.

csCMake works out the dependencies between components from the links of their targets: if `text` links `core`,
loading `text` loads `core` first. A cycle between components fails `cs_finalize_project`.

Every package also has the component `cscmake_common`, a default component holding the default target
`<namespace>::cscmake_base_include`.

## What is installed

Under the install prefix:

```text
bin/                                  executables, DLLs, PDB files (Windows)
lib/                                  libraries
include/[<CONFIG>/]<path>/            headers (*_INSTALL), at their path relative to the project folder
lib/cmake/<namespace>/
  <namespace>Config.cmake             generated by csCMake
  <namespace>ConfigVersion.cmake      compatible with any newer version
  targets/<component>Targets.cmake    one file per component
```

Headers go in an `include/<CONFIG>/` sub-folder when the project has more than one configuration, so that every
configuration can be installed in the same prefix.

## Using an installed package

```cmake
find_package(myApp COMPONENTS core REQUIRED CONFIG)
target_link_libraries(consumer PRIVATE myApp::core)
```

The generated `<namespace>Config.cmake`:

- loads the requested components (or the default ones) and the components they depend on, each once;
- calls `find_dependency` for the packages the components need: the `PUBLIC` ones of `cs_find_package`, and the other
  csCMake projects of the same build they link;
- sets `<namespace>_<component>_FOUND` for every requested component; an unknown component requested as `REQUIRED`
  makes `find_package` fail, with the list of the available ones in `<namespace>_NOT_FOUND_MESSAGE`;
- sets `<namespace>_BASE_DIR` (the install prefix of the package), `<namespace>_CMAKE_DIR`,
  `<namespace>_COMPONENTS_LIST`, `<namespace>_DEFAULT_COMPONENTS_LIST` and `<namespace>_<component>_DEPENDENCIES`;
- has its own debug option: `-D<namespace>_DEBUG=ON` prints what it loads (a `-` in the namespace becomes `_`).

## Inside the project

`cs_get_components`, `cs_get_default_components`, `cs_get_component_targets`, `cs_get_component_dependencies` and
`cs_get_target_component` return what the project installs; `cs_print_components` prints it with the debug messages.
